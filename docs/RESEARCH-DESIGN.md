# 个股基本面研报模块设计

> 目标：对单只 A 股采集基本信息 / 财报 / 公告 / 舆情，**确定性计算**基本面评分，再由 LLM 按章节撰写
> 解读，产出可存储、全站共享的结构化研报。
> 定位：研究辅助与信息整理，**不是投资建议**——不输出买卖评级、不给目标价。

---

## 1. 原则

1. **分数由代码算，LLM 只解释**——评分是纯函数 `score(facts, rules_version)`，同输入永远同输出；
   LLM 不参与任何打分；公告事件也由关键词规则分类（`research_facts.EVENT_RULES`），标签→分值由代码映射。
2. **LLM 不算数、不造数**——报告里出现的每个数字必须来自事实表（facts），写完后做数字校验。
3. **数据不足即标注，不凑数**——缺失指标不计分，所在维度按剩余权重归一；覆盖率写进报告。
4. **流水线，不是自主 agent**——采集 → 计算 → 撰写 → 校验，顺序固定；不做研报追问。
5. **共享 + 管理员管控**——研报全站共享只读；生成 / 重新生成 / 删除仅管理员可操作。
6. **规则带版本**——`scoring_version`（如 `v1`）随报告存储，改规则升版本，新旧分数不混比。

**口径注意**：
- 财报是**累计值**（中报 = 上半年）。增速用「累计同比」；需要年化的指标（ROE 等）用最近一个
  **完整年报**，或 TTM = 本期累计 + 上年年报 − 上年同期累计。
- 以 `公告日期` 而非 `报告日` 判定「当时可见」，为将来定量部分回测保留时点正确性。

## 3. 评分规则 v1.1（满分 100）

### 3.1 计分方式

每个指标用**分段线性**映射：给定「零分点」与「满分点」，中间线性插值，两端截断。
反向指标（越低越好）零分点大于满分点即可，同一公式处理。

缺失处理：指标缺失 → 不计分；维度得分 = 已得分 / 可用满分 × 维度满分。
若某维度可用满分 < 50%，该维度标记「数据不足」，不计入总分，总分按其余维度归一。
**整体覆盖率 < 70% 时不给评级**（显示「—」）。

### 3.2 指标与阈值

| 维度 | 指标 | 分值 | 零分点 → 满分点 |
|---|---|---|---|
| **盈利能力 20** | 最近年报 ROE（加权） | 8 | 5% → 20% |
| | 销售毛利率（最近年报） | 4 | 15% → 50% |
| | 销售净利率（最近年报） | 4 | 3% → 20% |
| | 近 5 年 ROE 标准差 | 4 | 10pp → 2pp |
| **成长性 20** | 营收 3 年 CAGR | 6 | 0% → 20% |
| | 扣非净利 3 年 CAGR | 6 | 0% → 25% |
| | 最新累计期扣非净利同比 | 5 | −20% → 30% |
| | 单季营收同比变化（最近季 − 前一季） | 3 | −10pp → +10pp |
| **财务健康 15** | 资产负债率 | 6 | 70% → 30% |
| | 流动比率 | 4 | 1.0 → 2.0 |
| | 有息负债 / 货币资金 | 5 | 1.5 → 0.3 |
| **现金流质量 15** | 近 3 年经营现金流 / 净利润（均值） | 7 | 0.5 → 1.2 |
| | 近 3 年累计 FCF / 累计净利润 | 4 | 0 → 0.5 |
| | 应收增速 − 营收增速（同比） | 4 | +30pp → 0pp |
| **估值 15** | PE(TTM) 自身历史分位 | 5 | 90% → 10% |
| | PB 自身历史分位 | 3 | 90% → 10% |
| | PE(TTM) 同行业分位 | 7 | 90% → 10% |
| **股东回报 5** | 股息率 | 3 | 0% → 4% |
| | 近 3 年平均分红率 | 2 | 10% → 50% |
| **事件 10** | 近 180 天公告事件（见 3.3） | 10 | 基准 5 分，加减后截断到 [0, 10] |

定义：
- 有息负债 = 短期借款 + 一年内到期的非流动负债 + 长期借款 + 应付债券（新浪资产负债表科目）。
- FCF = 经营活动产生的现金流量净额 − 购建固定资产、无形资产和其他长期资产所支付的现金。
- PE ≤ 0（亏损）时两项 PE 分位指标均记 0 分（不是缺失）。
- 业绩恶化让比值无定义时按规则给分，不当缺失（v1.1；否则维度归一会替它免掉扣分）：
  - 最近年报扣非净利润 ≤ 0 → 扣非 3 年 CAGR 记 0 分；起点 ≤ 0、终点 > 0（扭亏）仍视为缺失。
  - 近 3 年累计净利润 ≤ 0 → 经营现金流 / 净利润、FCF / 净利润两项：对应累计现金流 > 0 记一半分，否则 0 分。
- 自身估值历史不足 480 个交易日（约 2 年）且同行业分位可用时，PE / PB 自身分位权重各减半，
  减下的 4 分加给同行业分位（5/3/7 → 2.5/1.5/11），条目注明实际天数（v1.1）。
- 同行业分位按 `StockInfo.industry` 分组，组内有效样本 < 10 只时视为缺失。

### 3.3 事件分

公告标题按**关键词规则**分类（含排除词，如「回购注销限制性股票」不算回购、「终止减持」不算减持），未命中归 `other`。
不用 LLM 分类：事件分进总分，必须可复现；规则同样便宜、可单测。标签与分值：

| 标签 | 分值 | 标签 | 分值 |
|---|---|---|---|
| `buyback` 回购 | +2 | `reduce` 股东减持 | −2 |
| `increase` 股东增持 | +2 | `inquiry` 问询函 / 监管函 | −2 |
| `incentive` 股权激励 | +1 | `investigation` 立案调查 | −5（同时触发排雷） |
| `forecast_up` 业绩预增 | +1 | `forecast_down` 业绩预减 / 亏损 | −2 |
| `major_contract` 重大合同 | +1 | `lawsuit` 重大诉讼 | −1 |

同类标签只计一次（最多计一次绝对值最大的），防止公告数量放大分值。

### 3.4 排雷项

命中任一条：评级**封顶 C**（总分不改），报告摘要置顶显示。
其中 **ST / *ST 与立案调查直接定 D**（v1.1）：C 会被读成「中等」，与这两类风险的严重程度不符。

| 排雷项 | 判定 | v1 可用性 |
|---|---|---|
| ST / *ST | 证券简称含 ST | ✅ |
| 商誉过高 | 商誉 / 归母净资产 > 30% | ✅ |
| 存贷双高 | 货币资金 / 总资产 > 20% 且 有息负债 / 总资产 > 20% | ✅ |
| 持续亏损 | 最近两个完整年度扣非净利润均 < 0 | ✅ |
| 立案调查 | 事件标签 `investigation` | ✅ |
| 非标审计意见 | 公告标题含「非标准审计意见」「保留意见」「无法表示意见」 | ✅（标题级，P3 改读审计报告） |
| 大股东高质押 | 控股股东质押比例 > 50% | ⏳ P3（东财质押接口，不稳定） |

### 3.5 评级

| 评级 | 总分 |
|---|---|
| A | ≥ 80 |
| B | 65 – 80 |
| C | 50 – 65 |
| D | < 50 |

页面统一称「基本面评级」，避免与券商投资评级混淆。

### 3.6 适用范围

v1 **不支持金融类**（银行 / 保险 / 证券 / 多元金融）：报表结构不同，上述指标不适用。
按行业判定，生成请求直接拒绝并提示。

## 4. 存储

```python
class ResearchReport(Base):        # 全站共享，一次生成一行（保留历史）
    __tablename__ = "research_reports"
    id, code(index), name, industry
    status            # queued / running / done / failed
    progress          # 当前步骤文案：采集财报 / 计算评分 / 撰写 3/8 章…
    created_by        # 触发的管理员 user_id
    data_as_of        # 最新报告期，如 "2026-06-30"
    scoring_version   # "v1"
    total_score: float | None
    grade: str | None # A/B/C/D/None（覆盖率不足）
    coverage: float   # 指标覆盖率
    sub_scores: JSON  # {维度: {score, max, items:[{key, value, points, max}]}}
    red_flags:  JSON  # [{key, label, detail}]
    facts:      JSON  # 完整事实表快照 {fact_id: {value, unit, label, source, period}}
    sections:   JSON  # [{key, title, md, metric_keys}]——前端按章渲染（指标表由前端据 sub_scores 渲染）
    content_md: Text  # 研报全文 Markdown（导出用）
    sources:    JSON  # [{source, fetched_at, url?}]
    llm_model, llm_tokens, error
    created_at, finished_at

class ResearchRawCache(Base):      # 原始数据缓存（跨报告共享）
    __tablename__ = "research_raw_cache"
    source, code, key (联合主键), payload: JSON, fetched_at
```

- **当前报告** = 该股票最新一条 `done`；历史保留，用于分数走势。
- **去重**：同 code 已在队列（queued / running）直接拒绝；同 code + 同 `scoring_version` 当天（北京时间）已有 `done`，需显式 `force=true`
  （提交时还不知道 `data_as_of`，所以按「当天」判断）。
- **缓存 TTL**：财报 7 天、公告 1 天、新闻 6 小时、基本信息 30 天。
- 建表沿用项目现状：启动时 `Base.metadata.create_all` 创建新表（Alembic 链目前只有初始 schema）。

## 5. 执行流水线

```
管理员提交 codes[] → 每只建一行 status=queued
APScheduler 每 30s 取 1 条 queued 执行（max_instances=1，串行——ECS 1.8G 内存）
启动时把残留的 running 重置为 queued（容器重启不丢任务）

1. 采集      各源独立 try，失败记入 sources 的 error 字段，不中断
2. 事实表    解析/清洗 → facts（每个数字一个 fact_id，如 roe_2025 / gross_margin_2025）
3. 事件分类  公告标题 → 关键词规则 → 枚举标签
4. 评分      score(facts, events, "v1") → sub_scores / red_flags / total / grade
5. 撰写      按章调用 DeepSeek，输入仅该章相关的 facts 子集
6. 校验      数字校验 + 禁用词校验，不通过重写 1 次，仍不通过则该章附「待人工核对」标注
7. 落库      status=done
```

### 5.1 研报结构

1. 摘要：评级、总分、维度得分条、排雷提示、3 条核心观察（LLM）
2. 公司概况与主营构成
3. 盈利能力
4. 成长性
5. 财务健康与现金流
6. 估值
7. 同业对比（§11，本地因子快照无同业样本时省略）
8. 近期重大公告
9. 新闻与机构观点
10. 风险提示
11. 后续跟踪（§11，纯代码生成）
12. 附录：评分明细、数据来源与抓取时间、免责声明

第 3–6 章开头是代码渲染的指标表，其后为 LLM 解读；第 10 章全部由代码生成。

### 5.2 LLM 约束

- 模型：`deepseek-flash`（关闭思考模式），JSON mode，输出 `{"markdown": str, "cited": [fact_id]}`。
- 提示词明确：只能使用给定 facts 中的数字；不得出现买入 / 卖出 / 增持 / 减持建议 / 目标价。
- **数字校验**：从 markdown 中正则抽取所有数字，每个必须能匹配某个 fact 值（按显示精度四舍五入后
  相等，百分数与小数互认）；年份、章节号、「3 年」这类计数词放白名单。
- **禁用词校验**：「建议买入」「目标价」「强烈推荐」等命中即重写。
- 无 `DEEPSEEK_API_KEY` 时：流水线照常跑完评分，正文只含代码生成的表格 + 「AI 解读不可用」占位
  （与项目「零依赖也能跑」一致）。

## 6. API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/research` | 登录用户 | 每只股票的当前报告（最新 done），按总分降序；筛选在前端做 |
| GET | `/research/{id}` | 登录用户 | 报告详情（sub_scores / red_flags / sections / facts / sources） |
| GET | `/research/{id}/markdown` | 登录用户 | 全文 Markdown（导出下载） |
| GET | `/research/stock/{code}/history` | 登录用户 | 该股票历次报告的分数走势 |
| POST | `/admin/research` | 管理员 | `{codes: [...], force?: bool}` 批量提交，逐只返回受理结果 / 拒绝原因 |
| GET | `/admin/research/tasks` | 管理员 | 最近任务（含 queued / running / failed） |
| POST | `/admin/research/{id}/retry` | 管理员 | 失败任务重新排队 |
| DELETE | `/admin/research/{id}` | 管理员 | 删除报告 / 取消排队（运行中不可删） |

普通用户看不到 queued / failed 记录。

## 7. 前端

### 7.1 路由与入口

| 路由 | 页面 | 权限 |
|---|---|---|
| `/app/research` | 研报库（管理员额外有「生成研报」按钮 +「任务队列」标签） | 登录用户 |
| `/app/research/:id` | 研报详情 | 登录用户 |

- 侧边栏只加一项「研报」（行业之后）；不单独做管理页，管理能力内嵌在研报库页。
- 其他页面联动：选股 / 自选 / 行情表中有研报的股票显示评级小标签，点击进详情（P3）。

### 7.2 研报库

- 顶部评级分布卡（覆盖数 + A/B/C/D 计数，点击即筛选）。
- 筛选：代码 / 名称搜索、行业、只看有排雷；默认按总分降序。
- 表格列：股票、行业、评级、总分、各维度迷你条（7 根，高度 = 得分率，hover 显示明细）、排雷数、报告期、更新时间。
- 报告期距今 > 120 天灰显「可能过期」。

### 7.3 详情页

- 头部：名称 / 代码 / 行业、报告期、生成时间、规则版本、历史版本下拉（管理员可在此删除版本）。
- 免责声明置顶 + 置底。
- 评分卡：评级 + 总分 + 覆盖率 + 分数走势（≥2 次报告时显示）；右侧 7 维度**横向得分条**（不用雷达图：
  面积夸大差异、轴序影响观感）。
- 排雷提示（有才显示，红色，最醒目）→ 核心观察。
- 正文：左侧固定目录；每章 = 前端据 `sub_scores` 渲染的指标表（hover 数值显示来源 / 报告期）+ LLM 解读
  （`react-markdown` + `remark-gfm`）。
- 附录：完整评分明细（原始值、得分 / 满分、零分点 → 满分点），评分规则公开透明。
- 正在重新生成时显示「更新中」，内容仍展示旧版本。

### 7.4 配色

评级**不用红绿**（与 A 股红涨绿跌冲突）：A → D 使用单色系深浅（深靛 → 灰）；红色只留给排雷。
图表沿用手写 SVG（同 `rrg-chart` / `backtest-chart`），不引入图表库。

### 7.5 管理员

- 「生成研报」对话框：粘贴多个代码（逗号 / 空格 / 换行分隔），可勾选「强制重新生成」；
  后端返回逐只受理结果（金融类 / 代码不存在 / 当日已生成会被拒并说明原因）。
- 任务队列：状态、股票、进度、提交时间、错误信息；失败可重试，排队中可取消。
  有 queued / running 时 `refetchInterval` 3s 轮询，否则停止。

## 8. 合规

- 每份报告顶部和底部固定免责声明：「本报告由程序基于公开数据自动生成，仅供研究参考，不构成投资建议」。
- 不输出买卖评级与目标价；「基本面评级」只反映财务数据的规则化评分。
- 附录列出全部数据来源与抓取时间。
- 站点维持邀请制。

## 10. 定期报告深读（P3，2026-10-19 设计；同日扩展到半年报 / 季报）

> 目标：把年报「第三节 管理层讨论与分析」里公司自己的解释、经营数据、自述风险带进研报，
> 取代正文里「需结合公告进一步确认」式的空泛表述。**不进评分**（依赖 LLM 抽取、跨公司不可比，评分仍是 v1）。

### 10.1 实测（贵州茅台 143 页 / 立讯精密 309 页，2025 年报）

- 年报不在「近 180 天公告」里（茅台 4-17 发布），需单独查：
  `stock_zh_a_disclosure_report_cninfo(category="年报")`；详情页 URL 的 `announcementId` + `announcementTime`
  可换算 PDF 直链 `http://static.cninfo.com.cn/finalpage/{日期}/{announcementId}.PDF`。
- 解析库用 **pypdf**（BSD）。PyMuPDF 快 3 倍且带书签，但 AGPL，与本项目 MIT + 网站形态不兼容。
  pypdf 309 页 6s / 81MB；读到「第四节」即停，实际只需前 ~60 页。
- 2021 年起年报格式统一：`第三节 管理层讨论与分析` → `第四节 公司治理…`，行首正则即可定位（跳过目录页）。
- 篇幅差异大：茅台该节 1.8 万字，立讯 7.2 万字（其中「主营业务分析」4.2 万字，以表格为主）。
- 小标题不统一：茅台「（四）可能面对的风险」，立讯的风险在「十一、公司未来发展的展望」内。
- 端到端实测：下载 + 解析约 2s，抽取约 5s / 1 万 token；茅台抽出 9 条公司解释、13 项经营数据、4 项风险，
  立讯 7 / 12 / 0（立讯展望里确实没写风险），校验丢弃 0 条。

### 10.1b 半年报 / 季报（2026-10-19 实测：金徽酒、茅台、立讯）

- **半年报**与年报同结构（第三节 → 第四节），小标题略有不同：「经营情况**的**讨论与分析」、
  「报告期内公司**所属**行业及主营业务情况说明」、风险在「五、其他披露事项 → （一）可能面对的风险」。
  金徽酒 2026 半年报：利润下滑原因（促销用酒、股份支付、补缴税款）写在「（二）其他披露事项」的质量回报行动方案执行情况里；
  应收账款 +211.69% 的原因在「资产、负债情况分析」表后的「注 2」。
- **季报**只有 12–14 页、没有 MD&A。唯一有归因的是「（三）主要会计数据、财务指标发生变动的情况、原因」表
  （项目 / 变动比例 / 主要原因，只列变动大的项目）；沪市行业公司其后还有「（四）销售情况」「（五）经销商情况」。
  无风险、无展望。
- 一年约 9 个月最新一期是季报（4 月底–8 月底一季报、10 月底–次年 4 月三季报），不读季报正文就会用旧期间的原因解释新数字。

### 10.2 流水线位置

```
事实表 → 【年报深读】 → 撰写
查年报列表 → 选目标年报 → 下载 PDF → 逐页抽文本（遇第四节停） → 切出 MD&A → 按一级小标题切块
→ 按优先级选块（≤ 3 万字） → LLM 结构化抽取 → 代码校验原文引用 → 通过的条目进入撰写
```

- **选报告**（`choose_reports`）：四类各查一次巨潮列表（不下载），取 年报 + 比它新的半年报 + 比两者都新的季报：
  4–8 月 = 年报 + 一季报；8–10 月 = 年报 + 半年报；10 月–次年 4 月 = 年报 + 半年报 + 三季报
  （三季报原因表太简略，上半年的事仍靠半年报）；新年报发布后只读年报。
  标题排除「摘要」「英文」；同期多份（更正 / 修订）取公告时间最新。
- **季报**不切小标题：「变动的情况、原因」到「二、股东信息」之间整节一块（≤ 8000 字）。页眉按整份文档统计。
- **选块优先级**：经营情况讨论与分析 > 可能面对的风险 > 主营业务分析（「XX 变动原因说明」）>
  资产及负债状况分析（「注 N：XX 变动主要原因」）> 行业经营性信息 > 展望 / 经营计划 / 发展战略 >
  其他披露事项（含质量回报 / 市值管理执行情况）> 核心竞争力 > 业务 / 行业。同一 key 多次出现时正文合并。
- **切块**：边界 = 已识别的块标题 + 停止标题（非主营业务、资产及负债、投资状况…）；块内其他同级小标题不切
  （立讯「一、消费电子业务」）。切前去掉页眉（半数以上页面重复的行）、页脚页码、「□适用 √不适用」行。
- **没配 DeepSeek key 时整步跳过**（不下载 PDF），来源标「未配置 AI，跳过年报深读」。
- **缓存**：不存 PDF；切出的文本存 `ResearchRawCache(source=f"{kind}_mdna", code)`（kind = annual / semi / q1 / q3），
  payload 带 `announcement_id`。无 TTL：公告 ID 变了才重新下载并覆盖——每类每只股票只保留最新一期；
  抽取结果存 `source=f"{kind}_extract"`，按 `announcement_id + EXTRACT_VERSION` 命中复用（每份报告一次 LLM 调用）。
  报告里用到的条目随报告的 `sections` 永久保存。
- **降级**：任一步失败（下载失败、扫描版文本过少、找不到章节、LLM 失败）→ 记入 sources，报告照常生成。

### 10.3 抽取与校验（守住「LLM 不造数」）

不把原文直接给撰写环节——那会让原文里所有数字都被放行，LLM 可能张冠李戴。分两步：

1. **抽取**：LLM 只摘录不解读，输出
   ```json
   {"drivers": [{"topic": "revenue|margin|expense|cashflow|capex|inventory|other", "claim": "…", "quote": "原文"}],
    "kpis":    [{"name": "…", "value": "…", "unit": "…", "quote": "原文"}],
    "risks":   [{"title": "…", "quote": "原文"}]}
   ```
2. **代码校验**（纯函数 `verify_extract`）：NFKC + 去空白后 `quote` 必须是原文子串（pypdf 会在句中断行），且不短于 6 字；
   `driver.claim` 里的数字必须都出现在其 `quote` 中，否则 claim 退回为 quote 原文（条目不丢——年报「XX 变动原因说明」
   常不带数字，LLM 会把上方表格的变动比例拼进 claim；a1 版因此在金徽酒上丢光了 9 条解释）；`kpi.value` 至少含一个数字且都在 `quote` 中（抽数字时保留空白、
   整体匹配千分位，否则表格相邻单元格会粘连）；页码由代码按 quote 回查原文，不信 LLM。不通过的条目丢弃。
   章节分配：margin / expense → 盈利能力；revenue / other → 成长性；cashflow / capex / inventory / balance → 健康与现金流。
   **合并**（`merge_extracts`）：各报告条目标出处 `doc`（如「2026 半年报」），按报告期由新到旧；风险取最新一份非空的
   年报 / 半年报（季报不披露；半年报常写「与年报相比无重大变化」，此时退回年报）。
   撰写时要求注明出处，且各报告的解释只能用于对应期间（年报 = 全年，半年报 = 上半年，季报 = 年初至季末）。
   kpis 除经营数据外，也摘录分地区（省内 / 省外）、分渠道（经销 / 直销 / 线上）收入及同比（a2 起）。
3. **撰写**：各章只拿到通过校验的条目；正文出现「事实中」「背景材料」「故此处仅陈述」等元话语视同校验失败，带错误重写；允许出现的数字 = 事实表 + 这些条目里的数字（不是整篇原文）。

### 10.4 报告呈现

| 位置 | 内容 | 生成方 |
|---|---|---|
| 盈利 / 成长 / 健康与现金流章 | 按 `topic` 分配的「公司解释」条目作为背景材料 | LLM 撰写（经校验） |
| 公司概况 | 「经营数据」表（kpis），每个数字标「年报第 X 页」 | 代码 |
| 风险提示 | 「报表风险」（评分 / 排雷）+「公司自述风险」（年报原文，不改写） | 代码 |
| 附录 | 年报标题、公告日期、巨潮链接 | 代码 |

撰写提示词不再要求「需结合公告进一步确认」，改为：年报有解释时引用公司解释，没有就直说「公司未披露原因」。

## 11. 同业对比 / 后续跟踪 / 参考指标（2026-10-19）

均**不计分**（评分仍是 v1，新旧报告分数可比）。

### 11.1 参考指标

章节可带 `info_facts`（fact id 列表），前端渲染为「参考指标（不计分）」小表。
- 健康与现金流：`contract_liab` 合同负债（无则取「预收款项」，2020 年新收入准则前的口径）、`contract_liab_yoy` 同比
  ——预收模式行业（白酒等）的领先指标。
- 同业对比：ROE（行情快照口径）、ROE / 市净率同行业分位（≥ 10 家才算）、同行业 ROE / 市盈率 / 市净率 / 股息率中位数。
- 估值与股东回报（机构一致预期，近 90 天研报，前两个预测年度，按年份分组展示）：
  - `fwd_pe_{y}` 前瞻市盈率 = 当前股价 / 预测每股收益均值（研报自带的市盈率是各自发布日股价，不用）；
  - `inst_eps_growth_fc_{y}` 预测增速：对上一年实际，没有实际就对上一年预测；
  - `inst_eps_fc_n/min/max/cv_{y}` 篇数、最低、最高、离散度（标准差 / 均值）——区间与离散度要 ≥ 3 篇；
  - `inst_eps_progress` 预测完成度 = 最新累计每股收益 / 当年预测，`eps_progress_prev` 去年同期累计 / 全年实际
    作季节性基准（年报期不算）。
  - 撰写提示：对照预测增速与最新实际增速、完成度与去年同期；不给合理价格或价格区间
    （禁用词加「合理价格 / 合理价位 / 合理股价 / 价格区间」）。
  - 不做 DCF / 正向估值区间：2026-10-19 用金徽酒、茅台实测，同一只股票换方法或假设结果差 2–5 倍
    （金徽酒 7–41 元），结论取决于我们拍的假设；反向 DCF 因基数（自由现金流 / 净利润）选择使隐含增速差一倍，暂缓。

### 11.2 同业对比

- 数据：本地 `FactorSnapshot` 最新截面按 `industry` 分组（申万口径，生产 125 个行业，最小也有 5 家），零新增数据源。
- 对比表：**市值（对数距离）最接近的 6 家** + 本公司，按市值降序——用行业龙头对比区域小盘股没意义
  （金徽酒的近邻是水井坊、酒鬼酒、舍得、口子窖、老白干、顺鑫）。
- LLM 写解读：只说相对位置，不推断原因；ROE 为行情快照口径，可能与年报口径不同，提示词与正文都注明。
- 毛利率、费用率的同业对比需要全市场财报，暂不做。

### 11.3 后续跟踪（`research_tracking.build_tracking`，纯函数，不经 LLM）

按组输出：
1. 排雷项（评分的 red_flags）；
2. 指标：异常规则（扣非同比 < −10%、营收同比 < 0、最近单季营收同比 < −10%、应收同比 > 30%、
   合同负债同比 < −15%、经营现金流 / 净利润 < 0.8、资产负债率 > 65%、市盈率自身分位 > 80%）
   + 评分项得分率 < 30%，同一指标只出一次；预测完成度比去年同期低 10 个百分点以上（全年一致预期能否兑现）；
3. 需跟进的负面公告（立案、非标、问询、减持、预减、诉讼，每类最新一条）；
4. 公司自述风险（定期报告深读）；
5. 下一期定期报告及法定披露截止日。

指标若在定期报告深读的公司解释里命中关键词（如应收 →「应收账款」、扣非 →「净利润」），附上最新一条及出处。

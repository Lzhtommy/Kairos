# Kairos Post-MVP 演进计划

> 配套文档：[`ARCHITECTURE.md`](./ARCHITECTURE.md)、[`MVP-TASKS.md`](./MVP-TASKS.md)（已完成）。
> 本文件把 MVP 之后的演进拆成 5 个阶段（P1–P5），每个阶段可独立交付、可验收。
> 排序原则：**先闭环（让策略自己跑起来），再诚实（回测可信），再上限（DSL 表达力），再差异化（AI 闭环），底座穿插还债。**

---

## 0. 阶段总览与依赖

```
P1 策略自动运行与推送 ──┐
                        ├──> P4 AI 研究助手闭环
P2 回测诚实度 ──────────┘
P3 DSL 表达力 ──────────> P2/P4 自动受益（回测与 AI 复用 DSL）
P5 工程底座 ─────────────  持续进行，不阻塞任何阶段
```

| 阶段 | 主题 | 预估 | 交付判定（一句话） |
|---|---|---|---|
| P1 | 策略自动运行与推送 | ~5 人日 | 用户不打开网站也能收到"策略命中变化"通知 |
| P2 | 回测诚实度 | ~8 人日 | 事件/组合两种模式输出账户净值口径、可交易性约束生效 |
| P3 | DSL 表达力：截面与量能 | ~7 人日 | "PE 全市场最低 10% 且放量突破"能生成、能筛选、能回测 |
| P4 | AI 研究助手闭环 | ~4 人日 | 回测完成后 AI 能基于结果给出诊断与改进建议 |
| P5 | 工程底座（持续） | 穿插 | DSL/回测有单测；数据断供 30 分钟内可感知 |

前置小任务（不成阶段，随手做）：
- [x] **东财 provider 回归 fallback 链**：本地/公司网直连已通（2026-07-29 实测）；push2 实时集群有 IP 级频控（连续十余次请求即临时断连），采集用 push2delay 或控制在分钟级频率；ECS 机房 IP 风控状态需上线前实测。
- [x] **数据新鲜度自检**：`GET /api/health/data` 返回 quotes 最后更新时间、K 线最新交易日、factor_snapshots 天数，供 P5 告警和人工排查用。

## P1 策略自动运行与推送（~5 人日）

**目标**：把"用户打开页面看命中"变成"系统盘后自动跑，命中变化推给用户"。产品从工具变成服务。

### 任务

- [x] **P1.1 策略运行记录表**（1d）
  - 新表 `strategy_runs(id, strategy_id, run_date, hit_codes JSON, added JSON, removed JSON, created_at)`
  - Alembic 迁移；`hit_count` 改为从最新 run 读取，删掉"打开详情页顺手刷新"的隐式行为
- [x] **P1.2 盘后调度任务**（1d）
  - APScheduler cron：交易日 15:25 CST（factor_snapshot 之后），遍历全部已保存策略跑 `run_dsl`
  - 与上一个交易日的 run diff 出 added/removed；幂等（当日已跑则跳过）
  - 复用 `in_trading_session` 的节假日判断口径：当日无新 K 线 bar 即视为非交易日，跳过
- [x] **P1.3 通知渠道**（2d）
  - 用户设置表加 `notify_channel`（none / email / webhook）与目标地址
  - 渠道一：SMTP 邮件（ECS 需用 465 端口，云厂商封 25）；渠道二：通用 webhook POST（企业微信/飞书/Server酱 都能接）
  - 只在 added/removed 非空时发送；单用户单日合并为一封（多策略汇总）
- [x] **P1.4 前端呈现**（1d）
  - 策略列表卡片显示"上次运行 {date}，新进 {n} / 调出 {m}"
  - 策略详情页命中列表旁边给出最近 5 次 run 的命中数走势（复用 sparkline）
  - 设置页：通知渠道配置 + "发送测试通知"按钮

### 验收

- 交易日 15:30 前，所有策略的当日 run 落库；某策略命中变化时对应用户收到且只收到一条通知
- 停机一天后恢复，不补发历史通知、不重复通知
- ECS 896MB 内存下全量策略串行跑完不 OOM（复用 `_CHUNK` 分批模式）

### 风险

- 邮件送达率（个人域名易进垃圾箱）→ 首选 webhook，邮件作为备选
- 策略数量增长后 15:25–15:30 跑不完 → 串行 + 单策略超时保护即可，量级到百级再考虑队列（P5）

## P2 回测诚实度（~8 人日）

**目标**：消除会系统性高估收益的失真点，两种模式统一到"账户净值"口径。推送出去的命中若建立在失真回测上，信任消耗比没有回测更快。

### 任务

- [x] **P2.1 涨跌停不可成交**（2d）
  - K 线已有 open/high/low：一字板判定 `open == high == low` 且 |涨幅| ≥ 9.8%（ST 4.8%、创业板/科创板 19.8%，按代码段区分）
  - 事件模式：入场日一字涨停 → 顺延到次日可成交日，连续 3 日买不进则放弃该信号并计数；出场日一字跌停 → 顺延，最长顺延 5 日后按次日收盘强平
  - 指标新增 `skippedByLimit`（因涨停放弃的信号数），前端展示
- [x] **P2.2 事件模式账户口径**（3d）
  - 参数：`maxConcurrent`（最大同时持仓，默认 10）+ 初始资金 1.0，每笔 `equity / maxConcurrent` 等分
  - 同日信号多于空位时按信号股票代码稳定排序取前 N（可复现）；持仓中的信号忽略（沿用单股一笔）
  - 输出与组合模式对齐：净值曲线、年化、回撤、夏普 + 保留逐笔明细；`avgReturn` 等逐笔指标降级为次要指标
  - 前端回测页：事件模式也画净值曲线 + 基准对比（复用现有 EquityCurve 双线）
- [x] **P2.3 换手成本按实际比例**（1d）
  - 组合模式调仓日：成本 = `turnover_ratio × rate × 2`，turnover_ratio 按新旧权重向量的 L1 距离 / 2 计算
  - 事件模式不变（每笔本来就是完整开平仓）
- [x] **P2.4 历史因子回补（PIT 数据）**（2d）
  - 东财 datacenter-web 拉历史财务指标（季频 ROE/股息率）+ 已有日 K 重构估值因子，回填 `factor_snapshots` 至 760 日
  - 回补脚本一次性执行（本地跑完 scp 数据库或走 ECS 后台任务），此后靠每日归档自然积累
  - `pitPeriods / rebalances` 前端展示为"时点数据覆盖率"，让用户知道结果可信度
- [x] **P2.5 退市股披露**（0.5d，先披露不修复）
  - 完整消除幸存者偏差需要历史退市名单 + 退市股 K 线，免费源拿不全；先在回测页明示"股票池为当前上市股票，存在幸存者偏差，小市值/困境反转类策略收益偏乐观"
  - 东财退市列表接口调研留到 P5 之后

### 验收

- 同一策略 P2 前后回测对比：一字板密集的题材策略收益显著下降（人工抽 3 个案例核对逐笔明细）
- 事件模式净值曲线与逐笔明细能相互印证（抽样 10 笔手工复算）
- `factor_snapshots` 覆盖 ≥ 2 年，组合模式 `pitPeriods` 占比 > 80%

## P3 DSL 表达力：截面算子与量能（~7 人日）

**目标**：从"绝对阈值筛选"升级到量化选股的主流表达：截面排名、多因子打分、量价形态。DSL 加什么，选股、AI 对话、回测就自动获得什么。

### 任务

- [x] **P3.1 截面算子**（2d）
  - filter 新增 `op: rank_top / rank_bottom / pct_top / pct_bottom`，`scope: market / industry`
  - 例：`{"factor":"pe","op":"pct_bottom","value":10}`＝PE 全市场最低 10%；`{"factor":"roe","op":"rank_top","value":5,"scope":"industry"}`＝ROE 行业前 5
  - `dsl.execute` 改两遍式：先算截面分位/名次，再逐行过滤；`validate_dsl` 同步扩展
- [x] **P3.2 多因子打分**（2d）
  - DSL 新增顶层 `score` 节：`{"score": {"factors": [{"factor":"roe","weight":0.6,"direction":"desc"}, ...], "top_n": 30}}`
  - 各因子截面标准化（rank 归一，回避分布假设）后加权求和，取前 N
  - 组合模式回测的 `maxPositions` 排序依据从"写死按市值"改为：有 score 用 score，否则保持市值
- [x] **P3.3 量能与常用指标**（2d）
  - technical 新增：`vol_surge`（当日量 ≥ N 日均量 × k 倍）、`breakout`（收盘创 N 日新高）、`macd_cross`（DIF 上/下穿 DEA）、`rsi_range`（RSI 落于区间）
  - `technical.py` 补对应 signal 函数与 `bars_needed`；K 线已有 volume，无新增数据依赖
- [x] **P3.4 AI prompt 与代码渲染同步**（1d）
  - `_spec_doc` 补新算子/score/新形态的说明与示例；`_render_code` / `_render_explanation` 支持新节点
  - 实测 10 条自然语言（含"低 PE 前 10%""行业内 ROE 前三""放量突破 60 日新高"）生成正确 DSL

### 验收

- 选股页策略筛选、盘后 run（P1）、回测（P2）对含 rank/score/量能的策略全链路可用
- DSL 校验对新算子的非法参数（负分位、weight 不归一）给出明确报错

## P4 AI 研究助手闭环（~4 人日）

**目标**：把回测结果喂回对话，AI 从"翻译器"变成"研究助手"。依赖 P2（结果可信才值得分析）。

### 任务

- [x] **P4.1 回测上下文注入**（1d）
  - `ChatIn` 新增 `lastBacktest`（前端把最近一次回测的 metrics + 分期收益摘要带上，控制在 ~1KB）
  - `chat_stream` system prompt 增补【最近回测】节 + 指引："用户询问回测结果时结合数据分析归因，提出可执行的改进方向并生成修改后的 DSL"
- [x] **P4.2 自动诊断回合**（2d）
  - 回测完成后前端在对话流插入一条系统消息："回测完成：年化 x%，回撤 y%。点击让 AI 诊断"
  - 诊断请求走既有 chat 接口（固定诊断 prompt 模板），产出诊断文本 + 可选的改进版 DSL（走既有 `<DSL>` 协议，右侧面板可一键采纳）
- [x] **P4.3 分期归因数据**（1d）
  - 回测结果补充"最差 3 个调仓期 / 最差 5 笔交易"结构化摘要，供诊断 prompt 使用（数据已有，只是聚合）

### 验收

- "为什么这个策略 2022 年亏得多？"能得到基于分期数据的归因，而非泛泛而谈
- AI 给出的改进 DSL 可直接回测，形成"生成 → 回测 → 诊断 → 改进"循环，全程不离开策略工坊

## P5 工程底座（持续穿插，不设截止）

按触发条件做，而不是按顺序做：

- [x] **单测（触发：P2 动回测引擎之前）**：`server/tests/` 起步，先覆盖三块纯函数——`dsl.validate/execute`、`technical.signal_series`、`backtest` 两种模式的小型合成数据用例。P2 的每个失真修复先写红测试再改（回归保护）。CI 加 pytest 步骤。
- [x] **告警（触发：P1 上线后）**：复用 P1 通知渠道，数据新鲜度检查（quotes 落后 > 30 分钟且处于交易时段 → 通知管理员）；采集器连续 N 次失败同样告警。
- [ ] **回测任务队列（触发：回测 P95 > 30s 或出现并发排队）**：当前线程内跑 + 结果落 JSON 文件的模式先不动；到量再上 arq/RQ + Redis，ECS 内存是主要约束，届时评估升配。
- [ ] **Postgres 迁移（触发：SQLite 写锁冲突可观测，或用户 > 百级）**：SQLAlchemy + Alembic 已就位，迁移成本主要在数据搬运和 `db.merge` 批量写的性能重验；在那之前 SQLite + WAL 够用。
- [ ] **部署链路补全（低优先）**：nginx 配置纳入 CI（rsync + reload 加入 deploy.yml，需要 deploy 用户 sudo reload 权限）,消除"改了 conf 忘了手动同步"这类隐患。

## 不做清单（明确排除，避免范围蔓延）

- ❌ 实盘/自动交易对接：合规风险与券商接口成本远超当前阶段收益
- ❌ 分钟级/tick 级回测：数据存储与采集成本数量级上升，日线策略是当前用户画像的主场
- ❌ 策略社区/分享市场：先把单人闭环做扎实
- ❌ 自研因子库/另类数据：免费源做不出质量，商业源等有付费用户再谈
